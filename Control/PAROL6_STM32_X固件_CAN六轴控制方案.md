# PAROL6 改装臂：STM32 + 张大头 X 固件 CAN 六轴控制方案

状态：实施草案，2026-11-06。适用于 J1–J6 尽量统一采用张大头闭环步进电机、STM32 作实时主控的改装方案。**电机、驱动板、固件和通信小板尚未逐轴定型；文中的设计参数须经实物与台架验证后冻结。**

## 1. 已有依据与设计边界

- 用户已初步确定 STM32 主控、六轴优先采用张大头 **X 固件 + CAN**。本仓库已有 `硬件资料/张大头/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`（下称《X42S 手册》，引用其**印刷页码**）和 `PAROL6选型与控制方案.md`。手册介绍的是驱动系列能力，**不能据此断言拟购六套电机的实际扭矩、尺寸、接口或固件版本**。
- 原版 BOM 是 NEMA17 电机、两套 20:1 和一套 10:1 减速器、皮带及原 PAROL 控制板/TMC5160 的清单，并非当前改装的定型采购清单。原 BOM 还有 24 V/5 A 电源、若干限位/接近开关和常闭急停；改装后应重新核算供电与传感器数量，不能直接沿用容量。
- `Docs （项目文档）/J5_part_J6加长30mm_修改记录.md` 记载 J5_part 已为 J6 组件增加 30 mm 的 v2 STL。`J5_J6回转间隙计算.md` 的约 9.72 mm 是二维保守估算，新增横板与实物控制板仍需三维干涉检查。J6 的电机、减速器、驱动板外形与传动比尚待核验。
- 仓库 URDF 有六轴关节及参考限位，但其电机配置与 J5/J6 几何未按本次改装标定；URDF 的 `effort="300"`、`velocity="3"` 等是模型参数，**不得作为真实驱动能力或安全限值**（见 `parol6_description/.../docs/ACTUATION.md`）。

## 2. 系统架构与职责

```text
上位机/ROS/示教器（非安全关键）
             │ USB CDC / Ethernet / UART（择一或并用）
STM32：指令仲裁、关节坐标/限位、轨迹插补、六轴同步、反馈监控、故障状态机
  ├─ FDCAN（经典 CAN 扩展帧）─ 收发器 ─ 总线 ─ J1…J6 X 固件闭环驱动板
  ├─ 六轴回零/限位输入、急停回读、上电/接触器状态输入
  └─ 安全继电器/接触器许可、状态灯/蜂鸣器等输出
常闭急停回路 ─ 独立硬件切断驱动功率/使能许可；机械支撑或制动防止失电坠落
```

每轴驱动板完成电机相电流调节、编码器采样/校准和电机端闭环位置/速度执行；STM32 不重复实现驱动板内环。STM32 计算逆运动学（可放上位机）、关节空间路径、速度/加速度约束和目标位置，做**监督式关节外环**：比较命令与电机实际位置、跟踪误差和状态，决定减速、停止或故障。电机端磁编码器看不到减速器回差、皮带弹性和输出轴滑移；需要高精度或可信关节绝对角时，在输出端另装编码器并建立独立监控。外环不应在未识别驱动板内环响应前叠加强位置 PID，以免两个位置环相互争抢。

## 3. CAN 硬件与厂家协议

**物理层**：选择明确带 CAN 接口的驱动套餐和匹配供电版本。CAN_H、CAN_L 用双绞线沿臂干线串接，短支线接六节点；线缆屏蔽、信号地、隔离和接地方式依供电拓扑与卖家接口图确定。仅干线两端装终端电阻，先断电实测总线终端等效值及极性，再上电。STM32 的 FDCAN 控制器仍需外置 CAN 收发器；优先隔离收发器和隔离电源，驱动器各节点电源做熔断/限流。手册印刷第 28 页是厂家 CAN 多机接线图；**具体针脚、电平、是否内置终端不能从连接器外观推断**。手册第 19 页 `CAN_Baud` 说明出厂默认 500 kbit/s，最终所有节点与 MCU 必须统一实测配置。

**帧格式**（《X42S 手册》第 42–44 页）：标准 classic CAN 的 **29 位扩展帧**，非 CANopen PDO/SDO，亦非将 Modbus RTU 字节直接放入 CAN 数据域。发送帧 ID 为 `(Addr << 8) | Packet`；`Addr` 是厂家电机地址，0 是广播，`Packet` 从 0 开始。厂家逻辑命令的地址字节放在 CAN ID 中，数据域从功能码开始；8 字节以内用一个帧，超过 8 字节按顺序拆包，**每包数据域的首字节仍是同一个功能码**，后续数据连续切片。手册示例：`01 FD 01 0F A0 00 00 01 FA 00 00 00 6B` 对应 ID `0x0100` 数据 `FD 01 0F A0 00 00 01 FA`，再发 ID `0x0101` 数据 `FD 00 00 00 6B`。返回帧同样按地址/包号解析；`02` 成功、`E2` 参数/条件错误、`EE` 格式错误、`9F` 动作完成（第 43 页）。校验出厂为固定 `0x6B`，手册也列 XOR/CRC8/Modbus-RTU 选项；上线时锁定所选**厂家自由协议**校验方式并逐轴读回，不能混用。分包边界、帧间隔、超时、重试、重复命令是否安全均须在台架实测。

**通信适配层**：实现 `encode/decode`、按地址过滤、分包重组、每轴请求队列、应答与超时关联、`E2/EE` 解码、诊断计数；保存原始帧日志和固件版本。发控制命令前确认 `Response` 设置，防止同时应答造成负载或冲突。状态轮询使用位置、速度、相电流、位置误差、状态/报警、回零标志；可尝试定时返回（第 66 页起），但需测试六节点相位错开和总线仲裁。多电机命令 `0xAA` 的广播地址、长度、CAN 分包示例在第 49–50 页；其位置命令同步标志语义与普通逐轴命令不完全相同，先单独测试，**不要把聚合命令当作天然可靠的反馈确认**。同页注明 Modbus-RTU 暂不支持该多电机命令。

## 4. 运动、反馈与回零

### 4.1 坐标和约束

每轴建立版本化参数 `{驱动地址、方向符号、总传动比、关节零点偏置、机械软限位、最大关节速度/加速度/加加速度、最大允许跟踪误差、电流限值、回零策略}`。换算为 `电机角度 = 方向符号 × 总传动比 × (关节角度 − 零点偏置)`，位置数值的单位、正负和溢出按所用 X 指令实测。原资料给 J1 皮带比约 `96/15`、J2 行星 `20:1`、J3 约 `20×42/38`；J4/J5/J6 以**最终实物齿数/减速器铭牌**复核。不要把 URDF 限位直接写入真实控制器。

正常关节移动优先测试 X 固件的梯形位置**限电流**命令（第 55–56 页，命令 `CD`），由每轴目标、加减速、最大速度、最大电流及同步标志构成；主控还要将关节级限制换算成电机级，并在入队前检查路径中间点。手册第 59 页的快速梯形位置 `F1/FC` **要求 V2.0.0 以上固件**，只有实测版本符合才用；第 55 页文字/表格对最大速度上限有不一致处，任何字段范围都以实际固件回复和厂家勘误为准，不以手册上限作为工程运行值。电流限值由电机额定值、驱动器散热和关节负载测得；X42S 板卡宣称的最大电流不是任一电机可持续工作电流。肩、肘等重力轴先做静态保载、温升及失电下坠试验，再提升速度。

**六轴同步**：优先为六轴分别发送“同步标志=缓存”的目标命令，逐轴确认正确接收应答，再用广播 `00 FF 66 6B` 统一触发（第 37、60 页）；若某轴缓存失败，绝不触发其余轴，进入故障态并按台架验证过的流程清除所有缓存。接收应答并不证明缓存内容可读回，故须靠协议编码检查、发帧日志和台架试验降低风险。第 37 页还列 `0xAA` 多电机命令实现同时开始，台架比较两种方案的起动偏差、丢包恢复和带宽后定型。运动完成依实际位置、速度及状态确认，不能只凭收到命令的应答。轨迹插补周期与下发周期分开设计，先以低更新率的分段目标试验；厂家梯形命令的重规划/打断行为须验证，不宜直接按伺服总线做 1 kHz 位置流。

**回零**：电机磁编码器只有电机端角度；多圈关节上电的绝对关节位置并不能仅凭单圈编码值推出。六轴逐轴定义安全回零方向与关节传感器，优先使用装在关节侧的限位/接近开关，必要时做双向找边与固定退让，再记录零点偏置。手册第 29–34、61–65 页列单圈、限位和碰撞回零；对打印件、皮带和重力轴，**不选碰撞回零作为默认方案**。默认关闭上电自动回零，待主控完成传感器自检、姿态检查、功率许可后按顺序回零。第 32、34–35 页说明驱动板的 En/Stp 或通讯脚可复用限位输入；复用会占用原功能，需与 CAN 接口板引脚图逐项核对。主控应独立采集关键硬限位并形成故障输入；软件软限位仅在回零成功后有效。

### 4.2 实时性和初步负载预算

以默认 **500 kbit/s 经典 CAN**估算，29 位扩展帧、8 字节数据连同控制/CRC/位填充/帧间隔约 **130–160 bit/帧**（设计估算，示波/抓包复核）。六轴 `CD` 类长命令按每轴约 3 帧，约 18 帧/组；单次约 `18×150/500000≈5.4 ms` 的纯线速占用，还未算仲裁、间隔和应答。若每组再有约 18 帧反馈/轮询，20 Hz 时约 `36×150×20/500000≈21.6%`，50 Hz 约 54%；加故障/重发后 50 Hz 已偏紧。初版取 **20 Hz 目标组 + 分散的反馈轮询**作为台架起点，留足带宽给急停诊断与报警；真正频率由实测最坏帧数、最大响应延迟、抖动和轨迹误差确定。驱动板内部电流/位置环频率与总线周期不同，主控任务周期不应假称为驱动环频率。若后续要高频伺服目标流，可验证 V2 快速命令或增加第二路 CAN，但需重新做同步方案。

## 5. STM32 和板级接口

建议首版选 **STM32G474RE 级别**作主控候选：具备 FDCAN、定时器、足够 GPIO/ADC、看门狗和调试生态；若上位机、日志、运动学都在 MCU 内且资源不足，再评估 H7。先用 Nucleo/同级评估板 + 外置收发器台架验证，PCB 投板前按所选封装的数据手册/CubeMX 锁定复用功能、3.3 V 容限、隔离方案与功耗。CAN FD 控制器可配置为经典 CAN 扩展帧，**不得开启 CAN FD 数据帧**。以下是接口级**网络清单，不是未经核对的 STM32 物理脚号**：

| 网络/模块 | MCU 侧信号与数量 | 外围与验收点 |
| --- | --- | --- |
| CAN1 | FDCAN_TX、FDCAN_RX 各 1，CAN_STB/EN 1 | 3.3 V 兼容收发器，优先隔离；CAN_H/L、可选终端跳帽、ESD、共模/屏蔽接法；读回六节点 |
| 急停/功率许可 | ESTOP_N 输入 1、CONTACTOR_FB 输入 1、DRIVE_POWER_EN 输出 1 | 常闭急停经独立硬件回路控制接触器或安全许可，MCU 只监测并参与复位；检测粘连/失电 |
| 回零/硬限位 | HOME_IN[6] 至少 6；必要时 LIM_NEG[6]、LIM_POS[6] 共 12 | 光耦/电平匹配、滤波、断线判别；按每轴传感器实际数量收敛，避免把原 BOM 的传感器数当六轴齐备 |
| 上位机与维护 | USB_DM/DP 或 UART_TX/RX；SWDIO/SWCLK/NRST | 通信鉴权/超时、固件升级、参数备份和原始 CAN 日志导出 |
| 供电与监测 | 24 V 母线经电源模块到 5 V/3.3 V；VBUS_SENSE ADC、温度/故障输入若干 | 驱动供电范围及总功率按实物重算；欠压、掉电、反接、浪涌和分支保护 |
| 人机/附件 | 状态灯、蜂鸣器、夹爪输出按需求 | 输出默认安全态、开机无自运动 |

正式原理图应有逐脚表：MCU 封装脚号/复用 AF、驱动接口针号、线色、信号方向、有效电平、隔离边界、接地、上拉和故障默认电平；采购资料齐全后填写，不在本草案虚构具体引脚号。

## 6. 软件模块与安全状态机

模块划分：`CAN HAL/收发队列` → `ZDT X 协议/分包` → `节点管理与参数读回` → `轴对象（单位换算、方向、位置展开）` → `回零/限位` → `轨迹规划与同步提交` → `反馈监控/故障日志` → `上位机接口`。配置含版本、CRC、校准日期与电机/固件序列号；写入非易失存储采用双副本/回滚。控制任务固定周期运行，CAN 接收中断仅入队，解析和规划在任务中执行，关键队列满/超时进入故障而非静默丢帧。独立看门狗只在控制任务、CAN 监控与安全输入均正常时喂狗。

状态：`POWER_OFF → BOOT_SELFTEST → DISABLED → HOMING → READY → RUNNING → HOLD/FAULT → DISABLED`。只有急停释放、供电正常、各地址唯一、固件/校验/限值匹配、驱动无故障且必要回零完成，才允许 `READY`；接收新轨迹前检查起点接近当前实测位置。通信单轴掉线、跟踪误差过大、位置越界、驱动报警、回零超时、总线 bus-off、上位机超时均阻断新动作并进入预定停机策略。可恢复故障需人工检查和明确复位，复位不能自动使能或自动继续轨迹。

**停机分级**：普通停止可发厂家 `FE 98` 立即停止（第 60 页）并监控实际停稳；严重故障/急停走独立硬件断功率/使能，不以 CAN 命令成败为前提。手册第 50 页说明失能后电机轴可转动，因此肩/肘等垂直负载必须评估机械支撑、制动器或配重；切断电源可能导致下坠。上电时驱动功率默认断开、发送缓存清理/状态读回、实际位置与上次记录核对，任何未确认姿态先回零或人工安全恢复。急停按钮、硬限位和线缆断开都做实际动作测试。

## 7. 分阶段实施与通过条件

1. **采购前冻结接口**：拿到六轴电机及驱动板型号、通信小板、X 固件版本、外形/曲线/针脚图；核算传动、重力力矩、供电峰值及 J6 三维包络。
2. **单轴空载**：固定电机，按手册第 7–8、15 页要求完成首次空载校准；拆板/换电机后重校。先低电流、低速、小角度测使能、失能、位置正负号、`CD` 限流、反馈、`FE` 停止和断电重启行为，记录原始 CAN 帧。
3. **单轴带负载**：装传动及独立限位，低速回零、限位、超时、跟踪误差、失电重力保持/坠落试验；测温升和真实可用速度/电流。
4. **六节点总线台架**：各节点唯一地址，抓包检查分包、同步缓存与广播触发、答复仲裁、同时上电、掉线、bus-off、总线负载、错误重发和 20/50 Hz 延迟；只有所有节点确认缓存成功才触发。
5. **整臂低速**：先不带工具/载荷逐轴回零，确认运动方向、实际角度、硬/软限位；再空载六轴联动和已知轻载路径，逐步增加速度与负载。每阶段保存参数、示波/抓包与实测误差；不合格退回前一阶段。

## 8. 向卖家和装配方确认的清单

逐轴完整型号、额定相电流/供电范围、持续/峰值转矩与转速曲线、整机含后盖/驱动板/插头外形、轴径轴伸与减速器适配；尤其 J6 的尾部尺寸及 J5_part 加长件在全转角下三维干涉。明确 X42S 板卡是 V1.0 还是 V2.0、X 固件确切版本（`F1/FC` 是否 ≥V2.0.0）、CAN 小板/集成接口、针脚与线束、终端电阻/隔离/接地、节点地址和默认波特率。索取对应版本 CAN 协议示例/上位机与固件勘误，确认多电机命令、分包间隔、缓存失败的清除方式、位置命令打断规则、定时返回多机错峰方式、看门狗/失联停机能力。确认电机与驱动板能否配套安装和校准后发货，以及失能/掉电时重力轴所需制动或保载方案。
